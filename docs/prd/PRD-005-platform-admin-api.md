All requirements, the contract (§5), the open questions (§8) and the phase plan (§9) live in the source-of-truth PRD. This file lists **this repo's** share and the approach for the code here.

## Why this shape

- The backend has no cross-tenant API and no platform identity, so the console cannot be "wired" to existing fields; the API is designed first (backend PRD §4–5) and this repo consumes it.
- Money and totals are computed on the server (root `CLAUDE.md` §4). The report logic that lives here today (`lib/metrics.ts`, `lib/revenueReports.ts`, `lib/subscriptionReports.ts`, `lib/subscriptionHealth.ts`, `lib/storeHealth.ts`, `lib/storeStatus.ts`) is the **specification** for the server rollups; it moves to the backend with its tests, and this repo keeps only display derivations.
- The screens are done (`docs/design/`); nothing visual changes except the new auth steps and onboarding progress.

## Conventions for the code here

- **One Apollo client**, no ad-hoc fetch. Operations in `src/graphql/<domain>.ts` with `gql` and named operations; validated against the composed schema before each phase ships (root `CLAUDE.md` §5).
- **State.** Apollo cache for server data; React context only for session and UI state. No zustand or React Query (ADR-5 in `docs/architecture/solution-architecture.md` is answered by this choice; record it there when Phase 1 lands).
- **Types.** Generated from the schema (`graphql-codegen`, dependency approval needed) into `src/types/generated.ts`; `src/types/index.ts` keeps only UI-side types. Enums stay the backend values; labels through `display-labels.util.ts`.
- **Errors.** Branch on `extensions.code` only (`UNAUTHENTICATED`, `TOKEN_EXPIRED`, `FORBIDDEN`, `NOT_FOUND`, `BAD_USER_INPUT`, `CONFLICT`, `MFA_REQUIRED`, `ACCOUNT_DISABLED`); never on message text.
- **Secrets.** Access tokens in memory only; refresh in the HttpOnly cookie; nothing new in `localStorage`.
- **Docs per phase.** Update `docs/architecture/solution-architecture.md` (§2 context, §3 providers, §6 integration becomes current), `README.md` (env names), `CLAUDE.md` (§1 status, §4 data and state) and the changelog in the same change.
